# Phase 1 architecture: C310 to SRS

## Scope

This document describes only the current streaming MVP:

```text
Logitech C310 -> V4L2 / FFmpeg -> MJPEG decode -> NV12 conversion
    -> h264_rkmpp -> FLV / RTMP -> external SRS
```

It has no ASR, vision-language inference, TTS, GUI, reconnect loop, recording, or audio.

## Startup contract

1. Load and validate `config/config.yaml`.
2. Resolve the camera: explicit `camera.device` wins; otherwise search by configured camera name.
3. If `camera.disable_dynamic_framerate` is enabled, set the UVC `exposure_dynamic_framerate` control to `0` through `v4l2-ctl`.
4. Open the V4L2 device requesting exactly MJPEG, 1280×720, 30 FPS.
5. Open the required FFmpeg hardware encoder `h264_rkmpp` with NV12 input.
6. Connect an FLV output to the configured external SRS RTMP URL and write its header.
7. Start processing camera packets.

Any failure in this sequence is a startup failure. The process reports the reason and exits. Phase 1 never falls back to software H.264.

## Steady-state data path

```text
av_read_frame
  -> MJPEG decoder
  -> AVFrame
  -> swscale conversion to reusable NV12 AVFrame
  -> h264_rkmpp encoder
  -> encoded AVPacket
  -> av_interleaved_write_frame (FLV / RTMP)
```

The current MVP executes that path in one foreground process loop. This is intentional while validating format negotiation, encoder compatibility, timestamps and RTMP packaging. A future split into capture/encode/publish workers must preserve bounded buffering and must not introduce a software encoding fallback.

## Time and frame ownership

- Input packets are unreferenced immediately after decode submission.
- The decoded frame is converted to one reusable NV12 frame.
- Encoded packets are unreferenced immediately after publication.
- Output video timestamps use the configured FPS time base.
- No historical image queue exists in this stage.

## Observability

At the configured interval, the publisher reports:

- capture FPS;
- encode FPS;
- pushed packet count;
- error count.

`scripts/run.sh`, `scripts/preflight.sh` and `scripts/acceptance_10min.sh` retain runtime evidence in ignored `logs/` files.

## Failure and shutdown behavior

| Event | Phase 1 behavior |
| --- | --- |
| Invalid config | Exit before device access. |
| Camera not found / cannot open | Exit with device diagnostic. |
| Camera read failure | Stop publishing and exit non-zero. |
| `h264_rkmpp` unavailable / fails to open | Exit; do not use CPU encoding. |
| Initial SRS connection fails | Exit. |
| RTMP packet write fails | Count error and exit non-zero when the loop ends. |
| `SIGINT` / `SIGTERM` | Finish current loop, write FLV trailer, close RTMP and release FFmpeg contexts. The runner targets the publisher PID directly. |

Automatic reconnect is deliberately not implemented in Phase 1.

The preflight script performs a TCP reachability check for the configured SRS RTMP port. It is not authentication or publish permission verification; RTMP connection and publishing are still verified by the publisher itself.
