# VoiceEdgeMonitor 部署说明

本文说明当前 MVP 的部署方式。推荐拓扑是：

```text
Logitech C310
      ↓ USB
RK3588：ALSA + VAD + ASR + WebSocket 服务端
      ↓ LAN
主机/WSL：静态 Web 页面 + 浏览器
```

板端负责采集、处理和识别；主机只负责页面和监控。浏览器或主机断开不应停止板端主链路。

## 1. 前置条件

### RK3588 板端

- ARM64 Linux，已验证环境为 Ubuntu 22.04。
- C++17 编译器、CMake、pkg-config。
- ALSA 开发库和运行库。
- Boost.Beast 头文件，用于 WebSocket 服务端/CLI 客户端。
- Logitech C310 USB 麦克风。
- sherpa-onnx C API 运行库。
- SenseVoiceSmall int8 模型和 `tokens.txt`。

当前 C310 的基线参数：

```text
设备：hw:CARD=U0x46d0x81b,DEV=0
采样率：16000
声道：1
格式：S16_LE
Period：2000 frames
Buffer：8000 frames
```

USB 卡号可能变化，优先使用 `CARD=` 设备名，不要固定使用 `hw:1,0` 或 `hw:2,0`。

### 主机/WSL

- Python 3，用于提供静态 Web 页面。
- 浏览器支持 WebSocket、Canvas、Web Audio API。
- 主机可以访问 RK3588 的 WebSocket 端口。

主机不需要安装 ASR 模型，也不需要运行 ALSA 采集程序。

## 2. 准备板端资源

模型和运行库放在仓库外部，例如：

```bash
export SHERPA_ONNX_ROOT=/opt/voiceedge/sherpa-onnx
export SENSEVOICE_MODEL_DIR=/opt/voiceedge/models/sensevoice
```

应确认以下文件存在：

```text
$SHERPA_ONNX_ROOT/include/sherpa-onnx/c-api/c-api.h
$SHERPA_ONNX_ROOT/lib/libsherpa-onnx-c-api.so
$SENSEVOICE_MODEL_DIR/model.int8.onnx
$SENSEVOICE_MODEL_DIR/tokens.txt
```

不要把模型、运行库、真实配置或设备凭据提交到 Git 仓库。

## 3. 获取代码

在 RK3588 上准备项目目录，例如：

```bash
git clone https://github.com/johnjiamzhong-project/VoiceEdgeMonitor.git
cd VoiceEdgeMonitor
```

如果通过 WSL 部署源码，可以使用 `scp` 或 `rsync` 复制项目；不要复制本地
`build-*` 目录、模型和日志。

## 4. 板端构建

```bash
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DBUILD_TESTING=ON \
  -DVOICEEDGE_BUILD_ALSA=ON \
  -DVOICEEDGE_BUILD_WS=ON \
  -DVOICEEDGE_BUILD_ASR=ON \
  -DSHERPA_ONNX_ROOT="$SHERPA_ONNX_ROOT"

cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

如果只运行主机侧队列、协议和 VAD 测试，可关闭硬件依赖：

```bash
cmake -S . -B build-host \
  -DVOICEEDGE_BUILD_ALSA=OFF \
  -DVOICEEDGE_BUILD_WS=OFF \
  -DVOICEEDGE_BUILD_ASR=OFF \
  -DBUILD_TESTING=ON
cmake --build build-host --parallel
ctest --test-dir build-host --output-on-failure
```

## 5. 启动板端 WebSocket 服务端

先确认 C310：

```bash
arecord -l
arecord -L
```

启动 WebSocket 服务端：

```bash
build/ws_server \
  --bind=0.0.0.0 \
  --port=8765 \
  --path=/voiceedge \
  --device=hw:CARD=U0x46d0x81b,DEV=0 \
  --rate=16000 \
  --channels=1 \
  --period-frames=2000 \
  --buffer-frames=8000 \
  --asr-model="$SENSEVOICE_MODEL_DIR/model.int8.onnx" \
  --asr-tokens="$SENSEVOICE_MODEL_DIR/tokens.txt" \
  --asr-language=zh \
  --asr-provider=cpu \
  --asr-threads=2
```

默认监听地址：

```text
ws://<RK3588_IP>:8765/voiceedge
```

服务端当前无 TLS 和鉴权，只建议在可信局域网使用。

## 6. 启动主机 Web 页面

在主机或 WSL 的项目根目录执行：

```bash
python3 -m http.server 8080 --directory web
```

浏览器打开：

```text
http://127.0.0.1:8080/?ws=ws://<RK3588_IP>:8765/voiceedge
```

页面会显示：

- 板端在线状态和音频参数
- 实时波形
- VAD 状态和事件
- ASR 状态、文本和耗时
- XRUN、读取错误和重连状态
- 可选音频监听

浏览器音频必须点击“开始监听”后才会播放。外放会造成 C310 声学回授，建议使用耳机；页面提供音量和静音控制。

## 7. CLI 客户端

如果构建了 `ws_cli`，可以不用浏览器验证协议：

```bash
build/ws_cli \
  --host=<RK3588_IP> \
  --port=8765 \
  --path=/voiceedge
```

CLI 会输出 hello、状态 JSON、VAD/ASR 文本事件和二进制音频包统计。

## 8. 可选本地保存

默认不保存音频和识别文字。需要保存时，在服务端启动参数中加入：

```bash
--persist-dir=/data/voiceedge \
--persist-audio \
--persist-transcript
```

结果结构：

```text
/data/voiceedge/
├── transcripts.jsonl
└── recordings/YYYY-MM-DD/segment-00000001.wav
```

只保存 VAD 划分出的语音段，不保存持续静音。请自行设置磁盘容量、轮转和清理策略。

## 9. 验证清单

### 采集

```bash
build/capture_probe \
  --device=hw:CARD=U0x46d0x81b,DEV=0 \
  --period-frames=2000 \
  --buffer-frames=8000 \
  --run-ms=30000
```

确认没有持续 XRUN、读取错误或无限重连。

### VAD/ASR

使用 `pipeline_probe` 确认：

- `vad_started` 和 `vad_ended` 能产生。
- `asr_started` 和 `asr_final` 能产生。
- `asr_drops=0`、`asr_failures=0`、`asr_overflows=0`。

### WebSocket

- CLI 或浏览器能收到 hello、state、VAD、ASR 和音频消息。
- 浏览器刷新不会导致板端退出。
- C310 USB 重置时，服务端进入 `audio_state=reconnecting` 并尝试恢复。

## 10. 常见问题

### 页面反复“连接中/未连接”

检查板端服务端是否监听：

```bash
ss -ltnp | grep 8765
```

确认页面中的地址、端口和路径完全一致：

```text
ws://<RK3588_IP>:8765/voiceedge
```

### C310 录音失败

检查 `arecord -l` 和 `dmesg`。C310 可能因 USB 集线器、线缆或供电发生重置；服务端会自动退避重开，但硬件连接仍需保持稳定。

### 出现回音或共振

使用耳机、降低 Web 页面音量或点击静音。当前版本没有实现板端 AEC。

### ASR 没有结果

确认 `VOICEEDGE_BUILD_ASR=ON`、模型/token 路径有效，并查看 `asr_failed` 或 `asr_failures`。
