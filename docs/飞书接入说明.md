# Codex 接入飞书（单向 MCP + 双向应用机器人）

当前仓库提供两条链路：

- `tools/codex_feishu_mcp.mjs`：最小的 `feishu_send_text` 单向通知桥，通过自定义机器人 Webhook 发消息。
- `tools/feishu_codex_gateway.mjs`：双向网关，通过企业自建应用的长连接接收 `@` 消息，交给本地 Codex `app-server`，再用应用机器人回复。

## 配置环境变量

在启动 Codex 的同一台机器上设置，不要写入 Git、项目记忆或日志：

```bash
export FEISHU_WEBHOOK_URL='https://open.feishu.cn/open-apis/bot/v2/hook/REPLACE_ME'
```

如果飞书机器人启用了签名校验，再设置：

```bash
export FEISHU_WEBHOOK_SECRET='REPLACE_ME'
```

## 注册 MCP Server

先在当前 shell 设置环境变量，再注册命令。这样 MCP 配置只保存程序路径，不保存飞书凭据：

```bash
export FEISHU_WEBHOOK_URL='https://open.feishu.cn/open-apis/bot/v2/hook/REPLACE_ME'
export FEISHU_WEBHOOK_SECRET='REPLACE_ME'  # 未启用签名时可省略

codex mcp add edgesight-feishu -- \
  node /home/rambos/arm_test/EdgeSightAssistant/tools/codex_feishu_mcp.mjs
```

重新启动 Codex，使 MCP 进程继承这些环境变量。

查看状态：

```bash
codex mcp list
```

进入 Codex 后使用 `/mcp`，应能看到 `edgesight-feishu` 和 `feishu_send_text`。

## 使用边界

- 自定义机器人 Webhook 只能发送消息，不能接收聊天消息；双向链路必须使用企业自建应用机器人。
- 飞书凭据只通过环境变量传入。
- 双向网关不注入当前已经打开的 Codex TUI，而是启动一个独立的本地 Codex `app-server`，并按聊天复用独立会话。
- 不需要在 RK3588S 板端安装 Python、PyTorch 或 Transformers。

## 双向 @ 机器人网关

### 飞书后台配置

在飞书开放平台创建或使用一个“企业自建应用”：

1. 开启机器人能力，申请接收群聊中 `@` 机器人的消息权限：`im:message.group_at_msg:readonly`；如需单聊，再申请 `im:message.p2p_msg:readonly`。
2. 申请应用身份发消息权限：`im:message:send_as_bot`（或更宽的 `im:message`）。
3. 在“事件与回调 → 事件配置”中选择“使用长连接接收事件”，订阅 `im.message.receive_v1`（接收消息 v2.0）。
4. 发布应用版本，并把“应用机器人”加入目标群。测试时要 @ 这个应用机器人，不是之前的自定义 Webhook 机器人。

长连接只要求本机能访问公网，不需要公网 IP、域名或内网穿透；应用事件回调必须在 3 秒内返回，因此网关只入队，Codex 处理在后台完成。详见[飞书长连接事件订阅文档](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case?lang=zh-CN)、[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive?lang=zh-CN)和[回复消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/reply?lang=zh-CN)。

### 安装与启动

在本机项目目录执行：

```bash
npm install

export FEISHU_APP_ID='cli_...'
export FEISHU_APP_SECRET='...'             # 只在本机环境设置
export FEISHU_ALLOWED_CHAT_IDS='oc_...'    # 必填，多个值用逗号或空格分隔

# 可选：让 Codex 处理这个项目；默认就是当前目录
export CODEX_CWD='/home/rambos/arm_test/EdgeSightAssistant'

npm run feishu:codex
```

网关默认还要求群聊消息带 `@`，默认使用 `workspace-write` 沙箱和 `approvalPolicy=never` 以便无人值守处理。只应把可信的群聊写入 `FEISHU_ALLOWED_CHAT_IDS`；如改用用户白名单，可设置 `FEISHU_ALLOWED_OPEN_IDS`。不要把 `FEISHU_APP_SECRET` 写入仓库、项目记忆或日志。

常用可选项：

```bash
export FEISHU_REQUIRE_MENTION=true
export CODEX_SANDBOX=workspace-write       # 也可用 read-only
export CODEX_APPROVAL_POLICY=never
export CODEX_MODEL='...'                   # 不设置则使用 Codex 默认模型
```

网关会对同一聊天串行处理、按 `message_id` 去重，并将较长回复自动分片。停止网关使用 `Ctrl+C`。若 Codex CLI 未登录、应用未发布、权限不足或使用了旧的自定义机器人，错误会记录在本机终端，不会把密钥打印出来。
