# Phase 2 activation contract

## Intended business flow

```text
C310 USB microphone
  -> ALSA 16 kHz mono PCM
  -> keyword spotting
  -> activation state machine
  -> VAD command capture
  -> SenseVoiceSmall ASR
  -> structured text result
```

The video publisher remains a separate Phase 1 process. Activation must not
depend on the board speaker or on a VLC window: the authoritative development
evidence is a structured event log that can be read over SSH.

## Observable state transitions

```text
idle
  --wake word above threshold--> awaiting_command
  --speech starts--------------> capturing_command
  --speech ends----------------> processing
  --ASR final------------------> idle
  --ASR ignored----------------> idle
```

Every accepted or rejected wake event is formatted as a single line, for
example:

```text
event=wake_detected from=idle to=awaiting_command keyword="你好小视" score=0.910
event=asr_started from=awaiting_command to=capturing_command
event=command_ended from=capturing_command to=processing
event=asr_final from=processing to=idle text="桌上有什么？"
event=asr_ignored from=processing to=idle reason=ack_echo text="我在。"
```

Rejected and timeout cases are also observable:

```text
event=wake_rejected from=idle to=idle keyword="你好小视" score=0.410 reason=score_below_threshold
event=activation_timeout from=awaiting_command to=idle
```

The current listener defaults are a binary KWS acceptance gate, a 5-second
speech-start window, a 1.5-second post-result cooldown, and no post-ACK time
guard. These are target-board interaction values, not an AEC implementation or
a final acoustic calibration.

## Current implementation

`edgesight_activation` remains an external-model-free C++ state machine. It is
covered by `edgesight_activation_test` and does not alter the Phase 1 video
publisher. The optional `edgesight_audio` target now connects ALSA capture to
sherpa-onnx's C API and emits the controller's structured wake events.

The target-board runtime is installed outside the repository:

```text
/home/firefly/opt/sherpa-onnx-v1.13.4-linux-aarch64-shared-cpu
/home/firefly/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20
/home/firefly/models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17
```

The prebuilt runtime archive does not include development headers. Install
the matching v1.13.4 C API header before configuring the optional target:

```bash
scripts/install_sherpa_onnx_header.sh \
  /home/firefly/opt/sherpa-onnx-v1.13.4-linux-aarch64-shared-cpu
```

The tested configuration uses the chunk-8 int8 encoder and joiner with the
fp32 decoder, the CPU provider, and `zipformer2`. The C310 microphone is
opened as `hw:1,0` at 16 kHz, mono, `S16_LE`; its hardware period is 2000
frames and its buffer is 8000 frames. `plughw:1,0` is accepted as an explicit
override, but repeated board tests showed intermittent USB `Input/output
error` there, so it is not the default.

Build the optional target on the board with:

```bash
cmake -S . -B build-audio \
  -DFFMPEG_ROOT=/opt/ffmpeg-rockchip \
  -DSHERPA_ONNX_ROOT=/home/firefly/opt/sherpa-onnx-v1.13.4-linux-aarch64-shared-cpu \
  -DEDGESIGHT_BUILD_AUDIO=ON \
  -DBUILD_TESTING=ON
cmake --build build-audio --parallel
```

From the target project root, use the checked-in launcher for a reproducible
listener command. It keeps the fixed keyword file, model paths, device, and
threshold together:

```bash
scripts/run_audio_kws.sh --run-ms=45000
```

From WSL, the same command can be started without PowerShell line wrapping:

```bash
ssh firefly@192.168.0.200 '/home/firefly/EdgeSightAssistant/scripts/run_audio_kws.sh --run-ms=45000'
```

For a positive wake-only check, let the listener stop automatically immediately
after it prints `wake_detected`:

```bash
scripts/run_audio_kws.sh --stop-after-wake
```

For a wake-plus-command-window check, use `--stop-after-command`; it prints
`wake_detected`, `asr_started`, and `command_ended`, then exits. These two
options are mutually exclusive and do not change the normal default behavior.

The fixed Phase 2 wake phrase is `你好小视`. Its pinyin tokens must remain
space-separated in the sherpa-onnx keyword file; the repository copy is
`config/keywords.txt`. On the target board, deploy that file as
`/home/firefly/EdgeSightAssistant/config/keywords.txt` and run the listener
with the model files:

```bash
build-audio/edgesight_audio \
  --device=hw:1,0 \
  --keywords-file=/home/firefly/EdgeSightAssistant/config/keywords.txt \
  --tokens=/home/firefly/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/tokens.txt \
  --encoder=/home/firefly/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/encoder-epoch-13-avg-2-chunk-8-left-64.int8.onnx \
  --decoder=/home/firefly/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/decoder-epoch-13-avg-2-chunk-8-left-64.onnx \
  --joiner=/home/firefly/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/joiner-epoch-13-avg-2-chunk-8-left-64.int8.onnx
```

For deterministic board checks, `edgesight_audio --wave=<mono-16k-wav>`
replays a WAV through the same KWS C API and state machine. `--capture-only`
checks ALSA without loading a model. The sherpa-onnx C API exposes a
thresholded/binary keyword result rather than a calibrated confidence value;
the adapter therefore records an accepted trigger as `score=1.000` and logs
`wake_score_mode=binary_kws_trigger`. The model's `--kws-threshold` remains
the acoustic gate.

Use `--wave-realtime` with a WAV replay when testing time-based behavior such
as command timeout or cooldown; the default replay intentionally runs as fast
as possible.

The recommended KWS runtime is sherpa-onnx's C/C++ API with its Chinese /
English Zipformer KWS model. The recommended post-wake recognizer remains
SenseVoiceSmall int8. Official KWS model and API references:

- <https://k2-fsa.github.io/sherpa/onnx/kws/index.html>
- <https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html>
- <https://k2-fsa.github.io/sherpa/onnx/c-api/html/keyword_spotting.html>

The implementation now covers KWS, activation state transitions, command
window VAD, and optional post-wake SenseVoice ASR. The fixed `你好小视` wake
phrase has a positive live microphone result at the configured threshold; the
following command path through to `asr_final` and the cooldown rejection /
recovery sequence have also been confirmed on the target board with the fixed
C310 microphone path.

The command-window VAD is an energy gate over the 16 kHz PCM stream. Its
defaults are `vad_start_rms=0.015`, `vad_end_rms=0.012`, 125 ms minimum speech,
and 1000 ms trailing silence. It waits for one quiet chunk after the wake word
so the wake phrase itself is not reported as the command.

In the complete pipeline, an accepted `你好小视` wake also sends the short TTS
acknowledgement `我在` through the configured TTS socket. By default the
listener continues feeding the microphone stream to command VAD while that
acknowledgement is playing, so the user can begin speaking immediately. The
optional `--wake-ack-guard-ms` or `EDGESIGHT_WAKE_ACK_GUARD_MS` time guard can
still be enabled when the speaker echo is stronger than the command; setting
it to zero leaves input open. The complete launcher now also sends the TTS
far-end PCM through `/tmp/edgesight-aec-reference.sock` and applies the
target-board SpeexDSP acoustic echo canceller in 10 ms frames before KWS, VAD,
and ASR. Single-character Chinese questions such as `谁？` and `几？` remain
valid; the one-token noise guard is limited to one-byte ASCII fragments. The
`audio_started` event reports whether the runtime AEC loaded;
ACK/interjection ASR filtering remains as a final safety net. After wake the
listener allows up to 5000 ms for command speech to start. This is a start
window, not a whole-command deadline: once speech starts, it is allowed to
continue, and the command ends after 1000 ms of trailing silence. If no speech
starts in the window, the controller emits `activation_timeout` and returns to
idle. The acknowledgement can be changed or disabled with `--wake-ack` and
the TTS ack is only enabled when `--tts-socket` is supplied.

The checked-in launcher also supplies the target-board SenseVoiceSmall int8
model. Once command speech ends, the captured 16 kHz PCM window is decoded by
the sherpa-onnx offline C API. Obvious ACK/interjection echoes (`我在`, `嗯`,
`啊`, etc.) and a single decoded token are emitted as `asr_ignored` and are not
sent to the vision worker; normal short questions such as `几点？` remain
`asr_final`:

```text
event=command_ended from=capturing_command to=processing
event=asr_final from=processing to=idle text="..."
event=asr_ignored from=processing to=idle reason=ack_echo text="我在。"
```

The binary keeps `--asr-model` and `--asr-tokens` optional so KWS/VAD and ALSA
diagnostic runs can still be performed without loading the ASR model. The
standard `scripts/run_audio_kws.sh` path enables them by default.

For a repeatable target-board regression without a person speaking, run:

```bash
scripts/acceptance_audio.sh
```

It generates a temporary three-session WAV from the official KWS sample,
paces playback in real time, and retains only the structured event log under
`logs/`. The script checks accepted ASR, active-session rejection, cooldown
rejection, post-cooldown re-acceptance, and clean shutdown. Models and the
temporary WAV remain outside the repository.

For board diagnostics, `--command-timeout-ms`, `--vad-silence-ms`,
`--cooldown-ms` and `--wake-ack-guard-ms` can override the normal 5000 ms,
1000 ms, 1500 ms and 0 ms activation timings. The checked-in defaults remain
the production interaction values; overrides are useful for making event
timing observable during a manual window.

## Acceptance checks

The eventual board test must prove all of the following through the event log:

1. Background speech and a low-confidence match produce `wake_rejected`.
2. The configured wake phrase above threshold produces exactly one
   `wake_detected` and enters `awaiting_command`.
3. Normal following speech produces `asr_started`, `command_ended`, and
   `asr_final` with the decoded command text; an ACK/interjection echo may
   instead produce `asr_ignored` and must not send a vision request.
4. No command after the timeout is sent to ASR.
5. A repeated wake during an active session is rejected.
6. A wake during cooldown is rejected and a later wake is accepted.

The current reproducible checks are:

1. Use the model's supplied WAV and keyword file; the target board emitted
   `wake_detected` and rejected the second keyword while the activation was
   still active.
2. Replay the same WAV with a temporary `你好小视` keyword file; it emitted no
   wake event because that WAV contains the model's supplied official phrases,
   not `你好小视`. This is only a negative replay check; the repository keyword
   file above is the fixed live-test configuration.
3. Record the C310 microphone and replay the recording through the same KWS;
   the fixed phrase emitted `wake_detected` at thresholds from `0.05` through
   `0.25`.
4. Run the fixed listener live with `--run-ms=30000`; it emitted exactly one
   `wake_detected` for `你好小视`, then returned to idle on timeout.
5. Run `--capture-only --device=hw:1,0` and the full KWS listener for 15
   seconds; both completed with `audio_stopped` and exit code 0.

6. For a deterministic timing regression, replay a composite official-KWS WAV
   with `--wave-realtime --cooldown-ms=30000`; the first session must finish
   with `asr_final`, a second wake during the window must report
   `reason=cooldown`, and a third wake after the window must be accepted.

7. Run the fixed listener live with `--command-timeout-ms=15000`; the target
   board produced `asr_final text="现在几点？"` and stopped automatically.

8. Run `scripts/acceptance_audio.sh` on the target board to repeat the
   deterministic Phase 2 event-chain regression and retain its log.

9. Run the audio regression concurrently with a short
   `EDGESIGHT_ACCEPTANCE_SECONDS=20 scripts/acceptance_10min.sh` video run to
   verify that the independent video and audio processes coexist. This does
   not replace the required VLC observation for Phase 1.

The live cooldown rejection/recovery sequence has now also been verified with
the real C310 microphone. Phase 2 basic activation, VAD, ASR, and cooldown
state-path acceptance is complete.
